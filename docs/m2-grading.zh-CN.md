# M2 整卷闭环与 Fluent 2

更新：2026-10-18。M1 已提交并推送为 `308b33e`。M2 已接通代码与本地自动化验证；真实供应商／三份用户样卷的语义验收尚未完成，不以合成协议测试替代。

## 界面

新增要求采用 Microsoft Fluent Design 2。当前使用官方 Fluent UI React v9 的 FluentProvider、按钮、输入、选择、消息栏、对话框、标签、进度与复选框，并统一为 Fluent Icons。保留系统窗口边框，使用系统字体、蓝色强调色与紧凑导航。公式引擎按需加载，资源随前端构建，不加载外部脚本或 CDN。

密钥输入是刻意保留的例外：Fluent Input 内部也会保存非受控输入值，因此密钥继续使用只有 DOM ref 的原生 password 输入框，样式使用 Fluent tokens；不使用 onChange、value、defaultValue、React state 或查询缓存保存密钥。

材料详情中选择供应商／模型与原生思考配置，未知视觉或工具能力需要勾选主动测试。点击开始才发送材料给供应商；导入和后补附件不会调用模型。新任务固定最多 16,384 输出 tokens、60 次模型调用、20 分钟业务上限（在调用边界检查）；HTTP 每次 180 秒超时，显式可重试错误最多重试两次。认证、额度、参数错误直接结束。

左侧原页与右侧结果对照，点击来源或题图在原页高亮归一化区域。正文、公式、表格、图片引用、选项、小问、分值、标准答案、解析、知识点、学生作答与评分分别保存。常用字段有普通编辑表单，表格、图片和来源等可在“完整结构”中编辑；后者当前是带业务校验的 JSON 编辑器。直接覆盖当前内容，不做历史版本。

参考答案可同时导入或后补。独立“整理参考答案与匹配”任务只保存答案和匹配，保留未匹配原因，不修改已评分题目。核对后点击重新批改，才会产生新的模型请求。

## 页级 PDF 与资产

- 类型按魔数检测 JPG／JPEG、PNG、WebP、PDF。图片和 PDF 解析后的材料与参考答案合计最多 12 页；超过限制整批拒绝，不截断。
- 原 PDF 与原始图片完整保留。每个 PDF 页的 PNG 关联 `original_asset_id` 与从 0 开始的 `pdf_page_index`；`page_index` 仅是材料中的排序。
- PDFium 7881 的下载地址与 SHA-256 存在 `src-tauri/resources/pdfium-lock.json`。运行 `scripts/prepare-pdfium.ps1` 下载并验证。只加载应用显式路径，不回退系统 DLL；PDFium 单次初始化，完整文档操作串行。
- 预览栅格默认宽 2400、最大高 3600。模型按需读取整页、原分辨率裁片或旋转图，不固定栏数；旋转后的展示不改变来源区域的未旋转坐标体系。
- M1 旧 `pending_pdf` 材料提供显式升级，保留原 PDF 和首个来源页 ID。密码 PDF、损坏输入、缺失 DLL、页数或缓存大小超限返回明确错误。原件及页面缓存合计最多 256 MiB。
- 有在途任务时不能编辑该材料。已被题目／参考答案引用的页面不能直接删除；先编辑结果移除引用，避免留下失效来源。旋转和排序保留稳定 ID。材料改变后不展示旧输入的覆盖报告。
- DLL、解包许可证与测试资料不提交 Git。完整分发和干净系统安装仍属于 M5；发布资源路径尚需随发布包组装验证。

## 整卷运行与保存

`ai/grading.rs` 运行单个整卷上下文，复用 Responses／Messages／Gemini 原生适配及 SSE。每次工具往返保留协议原始上下文与签名。Gemini 工具使用 `parametersJsonSchema`，与递归题目 JSON Schema 对应。

工具为 `read_page`、`save_references`、`save_question`、`python`、`shell` 与 `finish`。参考答案任务没有保存题目或执行工具。Python／Shell 复用现有私有运行时、任务权限代理与宿主执行器；计算进程不注入供应商密钥。Windows Sandbox 生命周期尚未接入，不能把执行器错误冒充沙箱执行成功。

任务输入冻结材料、模型能力、思考与价格配置，不含密钥。Rust 工作线程读取系统凭据；前端和数据库只有引用。UI 不展示原始推理或协议上下文，只显示状态、持久化结果、用量与错误。

SQLite 迁移到版本 2，新增 `grading_runs`、`questions`、`model_calls` 和 PDF 原件页引用。同一材料稳定 `draft_key` 更新同一题，重复导入产生独立材料和独立题目。任务取消与所有结果写入共享互斥屏障，数据库另查运行状态及冻结输入；取消后的迟到写入被拒绝，已经提交的结果保留。重启不重放模型或代码。

保存和完成检查包括：

- 来源页所属材料、角色与区域边界；教师结果必须有原图证据和批注原文。
- 教师模式明确教师结果优先；重新批改保护已有教师证据与手动评分。
- 匹配参考答案必须作为 AI 评分依据，不能跨题关联；已有答案键不静默丢弃。
- 分数非负、不超过满分、判定一致、小问合计一致；未知满分／无法判定不制造得分。
- 空白卷没有作答记录；已作答但读不清的题标为无法判定并说明原因。
- `finish` 需要全部目标页均实际读取、覆盖项不重复也不缺页、题目来源与覆盖一致、本轮没有遗漏之前已保存题目。无法辨认和无题页明确写出原因。

覆盖校验不能证明模型没有漏掉图片中的某一道题，教师证据校验也不能独立证明 OCR 的内容正确；这些仍由真实样卷和人工基准验收。

## 验证

```powershell
npm ci
./scripts/check-m2.ps1
# 固定 PDFium、真实页渲染与 M1 旧材料升级
./scripts/check-m2.ps1 -Pdfium
# 自建数据的真实 Tauri / WebView2 验收，不调用供应商
./scripts/check-m2.ps1 -Pdfium -DesktopSmoke
```

Rust 合成 HTTP 验证三种原生整卷工具循环、图片往返、重复保存、漏页拒绝后修正，以及取消在途模型请求后释放队列；不读取系统密钥。存储测试验证教师／手动结果保护、参考答案独立整理、分数／小问／空白卷规则、跨导入独立与重启持久化。

桌面脚本用 `m2_fixture` 自建试卷与明确标记的合成结果，每次创建独立资料库，位置记录在 `output/m2-desktop-acceptance/latest.json`。报告和截图位于 `output/m2-desktop-smoke/`。900 px 测试是逻辑视口模拟，不是物理 125%／150% 缩放验收。
