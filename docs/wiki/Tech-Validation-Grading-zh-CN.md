# 题目结构、评分约束与保留规则

[首页](Home-zh-CN.md) · [技术内幕](Tech-for-nerds-zh-CN.md) · [English](Tech-Validation-Grading.md)

## 公共题干与有序评分项

`Question` 保存稳定 `draft_key`、原题号、公共 `stem`、来源区域、学科/题型、知识点、待确认内容、笔记和有序 `items`。每个 `QuestionItem` 独立保存稳定 `key`、印刷标签、题目内容、选项、满分、标准答案、解析和可选作答。没有小问的题目仍有一个评分项，通常标签和内容为空，完整题目文字放在公共题干。

每题包含 1–100 个评分项。印刷上的嵌套标签展平为 `(2)(a)` 等形式，当前格式不再使用递归 `Parts` 树。多个评分项时标签不能为空。评分项键在整卷唯一；页面覆盖引用顶层题目键，参考答案匹配评分项键。

文字、公式、表格、图片仍为独立类型块。图片可引用处理后的 `asset_id`，同时保留原件来源区域。工作流使用相对未旋转整页的归一化 `x/y/width/height`；MinerU 0–1000 四角坐标在 OCR 边界转换，并逆向映射显示旋转。

## 写入前校验

模型输出先兼容常见格式差异并记录被忽略的额外字段，再检查 Schema。存储 JSON 契约仍拒绝额外字段，类型反序列化检查结构，领域和仓储校验检查所有权与含义。题号、题干、材料页来源必填；稳定键最多 128 个 UTF-8 字节；单题序列化内容最多 1 MiB。

| 输入 | 结果 |
| --- | --- |
| 部分正确，2/4 分 | 分数与判定一致。 |
| 部分正确，4/4 分 | 拒绝；部分正确必须严格介于零分与满分。 |
| 待确认，实得 0 分 | 拒绝；待确认实得分必须未知。 |
| 满分未知但实得分确定 | 拒绝。 |
| 空白模式评分项包含作答 | 拒绝；不生成未作答评分。 |
| 参考答案来源为材料页 | 拒绝；参考证据须来自参考页。 |

全部评分项满分已知时才合计题目满分；全部评分项实得分已知时才合计实得分。不存在独立可编辑的父题评分或父子分数合计。

## 证据与受保护修改

作答分离学生答案、教师批注、参考匹配、AI 解答/分歧和评分。来源为 `Teacher`、`AiReference`、`AiSolution` 或 `Manual`。已有手动评分受保护，教师模式与自动识别模式还保留明确教师结果与证据。AI 不能创建手动来源或移除受保护评分项。

标准答案与解法分别保存在评分项的 `answer`、`explanation`，空白卷也生成，但不创建作答。旧字段 `attempt.ai_solution` 保持可读。可空的 `attempt.error_analysis` 单独说明错误或部分正确作答中有证据支持的错因，与评分理由分开。

补充作答页使用 `role=student`。切题计划和评分通过归一化 `student_regions` 提交证据；题目本身仍须引用材料页。匹配复用已有评分项键。`SaveStudentAnswersAsync` 将修改的作答标记为手动录入，清除过期评分证据并设置待确认判定；空白模式转为自动识别，试卷实得分清空。AI 保留录入文字，同时可更新未受保护的评分字段。

切题证据核对认可学生作答页中完全位于 `matched` 或 `blank` 评分项 `answer_bindings` 区域内的 OCR 块和检测题框，无须重复列入 `ignored_*_ids`。材料页证据仍须显式列入题目或忽略 ID。缺失或未知证据 ID 仍会拒绝切题计划，并在本地诊断日志中记录缺失证据及完整返回结果。

切题模型接收版式识别后实际生效的导入模式及其 `allowed_answer_binding_statuses`。已作答试卷的每个评分项都须使用 `matched`、`blank` 或 `unmatched`；印刷试题页没有笔迹，不代表可以跳过独立答题卡的评分。`none` 仅用于空白模式，或尚未确定模式的自动识别中没有学生作答的评分项。切题校验失败时，本地诊断日志记录生效模式、原因及完整返回结果。

评分项的 `answer_bindings.block_ids` 可直接引用作答 OCR 块。运行器在校验和评分前将 ID 解析为原始区域，避免重复抄写或错误合并坐标。OCR 未覆盖的补充作答区域仍使用 `regions`。未知 ID 和错误页面角色会被拒绝；未包含 `block_ids` 的旧计划仍可读取。

切题计划未通过校验时，会连同校验错误及证据 ID 交回切题模型修正，合计最多三次。每次保留返回产物，并记录模型用量和预计费用。计划通过校验后才保存题目；第三次仍不合法则任务失败。

独立解答输入不包含作答、答案和解析字段。Responses 调用使用由源生成序列化元数据导出的严格 JSON Schema 输出。直连 DeepSeek 也使用 Responses 的 Schema 字段。为兼容供应商，展开本地 Schema 引用，可空对象使用明确的备选类型。常见外层包装、字段别名、集合形式、数字字符串、得分/满分及归一化四角坐标先归一化再校验；版式结果结构错误时合计最多三次修正。解答 JSON 格式错误或评分项键变化可在已配置的单题轮次限制内修正。评分结果在接受前检查结构、评分项键、证据区域及领域评分规则，合计最多三次。小题满分缺失时，可依据出题惯例、相对难度、解题步骤和印刷题目总分估算；没有已有满分时，将估算值保存为小题满分，并要求实得分与之保持一致。已有满分保持不变。每次返回和校验错误均会保留，修正调用计入模型用量与预计费用。

Responses 的 `high` 或 `max` 推理强度默认分配 65,536 个输出 token，并受模型输出上限约束。显式配置的输出 token 限制仍优先。Responses 未完成事件会记录服务端原因、输出限制和用量，以区分额度耗尽和连接中断。

`ConfirmQuestionAsync` 清除题目的 `uncertainties`，保留笔记与评分，要求试卷空闲，不会把待确认判定变成已解决的判定。

重新识别复用稳定键。类型和领域校验通过后，工作流结果替换未受保护字段。个人笔记在识别后保留，但题目文字没有完整版本历史。

## 完成与集合规则

运行器在完成前检查 OCR 页面各出现一次、来源键有效、参考答案匹配有效评分项。整卷任务须在本次保存全部现有顶层题。仅整理参考答案的任务覆盖参考页，不能保存题目或试卷信息。

任一评分项部分正确、错误或未作答，整题进入错题。评分待确认或抄录有疑点时进入待确认；只有不确定性不代表已确定错误。完成只校验一致性，不能保证每个符号与评分正确。
