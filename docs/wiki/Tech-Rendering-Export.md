# Native reading, formula assets, and controlled PDF compilation

## Display and print share content, not a screenshot

Saved domain blocks are adapted into native reading controls and into ExamDocument print records. The viewer can be responsive and theme-aware while print uses fixed paper geometry. Export does not take a screenshot of the current window, so screen zoom is not the print scale.

Text, formulas, tables, and image regions remain separate. Formula source is retained for editing and fallback. Ordered items keep their own content and use consecutive parenthesized print numbers, rather than being flattened into an opaque image.

## Native formula path

VelociTex supports native formula reading and SVG generation for print. A formula conversion can fail or be too wide for the available column. The export path can retain source notation and issue diagnostics instead of silently deleting the expression.

For screen reading, `FormulaLineBreaks` splits eligible expressions at top-level operators while keeping fenced/braced groups intact. Unsupported constructs remain whole, indivisible runs fit the available width, and copying uses the complete original formula source. This changes responsive reading, not the fixed PDF layout.

That fallback is evidence preservation, not a promise of textbook typesetting for arbitrary LaTeX. A PDF can be successfully compiled while still requiring human formula inspection.

## Build a controlled print model

The UI gathers currently displayed saved questions, rejects unsaved quick edits, assigns sequential export numbers, and prints scores inline with each stem instead of adding an original-number paragraph. It uses generated image assets when present and otherwise crops figures through managed page services, deduplicates image bytes, and enforces budgets. The question edition rejects handwriting-marked figures in the shared stem and every item.

The document service chooses A4 portrait or A3 landscape with independently configurable columns and Questions or Answers. Question edition omits answer/explanation text and defaults to compact spacing. Optional subjective writing areas estimate height from answer length, line breaks, score, and column width. A separate optional measurement pass distributes remaining page/column space equally among those areas; answer edition prints standard answers and explanations. StudentAttempt is not used as the answer key.

## Compile data through a fixed template

Typst source is generated by the application. User/model text is quoted/escaped; image paths are generated controlled assets, not arbitrary input paths. The template supplies page geometry, typography, numbering, and part layout.

Compilation uses a private root and empty package/cache paths, clears Typst environment overrides, limits subprocess time, and collects bounded output. It does not accept a user-provided executable document template. Formula and image assets are generated inside the controlled export area.

## Destination and diagnostics

The UI reads the completed PDF before writing the picker-selected destination. This separates incomplete compilation from the final file write, although it is not a universal filesystem transaction guarantee.

Current printed prose typography targets Chinese/English with Windows NSimSun, while the reading view defaults to the interface sans-serif face; formula outlines use their own renderer. Japanese/Korean interface localization does not imply extra print-font coverage.

For verification, use document/media tests for structure and rendering contracts, then inspect actual PDF output for glyphs, fractions, long equations, table widths, figure crops, and page/column breaks. Physical printer settings remain outside the compiler.
