## 真实资料、旧凭据与回退

1. 退出旧版和所有正在使用这份资料的新版窗口。先确认原资料目录，并保留原版程序。不要只复制`study.sqlite3`主文件充当活动资料库备份，WAL中可能还有已提交内容。
2. 在新版“更多 → 导入旧版资料”选择旧资料目录。此入口只读打开原库，创建一致备份，再在独立新目录恢复和升级；校验完成后才切换到新副本。记录生成的备份及新库目录，保留`migration-receipt.json`。
3. 核对代表性旧资料的原件字节或哈希、页数/顺序/旋转、题目和小问、教师批注、手动评分、参考答案、任务历史及模型设置。原件可在本地比对，无需上传。
4. 在原Windows用户身份下检查旧模型凭据是否可用，再发一次最小授权请求。凭据不随资料备份导出；换账户或换电脑不可假设旧凭据可见，必要时由用户在设置重新填写。只记录“可用／需重新填写”，不记录密钥内容。
5. 用“更多 → 备份资料”生成新备份，再用“恢复备份”恢复至另一新目录，检查上述内容。分别测试取消、错误备份、损坏副本；失败不能覆盖当前库或原库。
6. 回退时退出新版，使用保留的原版和未改写的原库；若需恢复，先将完整备份恢复到另一新目录。新版产生的新写入不保证旧版可读，不能直接把新版库交给旧版继续写入。

期望：原资料、完整备份和新副本分别存在；校验或切换失败不宣称完成；旧程序及原库可用于回退；不同时让旧新版写同一库。

## Windows Sandbox

这项独立于本机Python计算和协议模拟。旧系统、缺少固定`wsb.exe` CLI或组件未就绪时应保持未就绪；Windows 10旧单实例Sandbox不能因为能手动打开就记为支持应用会话管理。应用不会自动启用Windows功能或提权。CLI路线要求Windows 11 24H2及相应已更新组件，实际版本另行记录。

1. 在不支持或未启用的电脑选择沙箱模式并开始任务。期望开始前明确说明实际将采用的执行环境与后果；可取消，不把本机执行标成已隔离。
2. 手动打开一个用户Sandbox并保留可辨识内容，再从应用请求沙箱任务。期望应用报告占用，不接管、不关闭该窗口、不向它发送命令。测试后由用户自行关闭。
3. 在没有现有会话的可用电脑运行一个简单授权计算。检查该调用目录的`ownership.json`：新随机会话ID属于本次调用，完成后为`stopped`；可在终端用系统`wsb list --raw`比对运行前后。只有本次会话被释放，不靠进程名关闭其他会话。
4. 分别取消、正常退出、制造计算超时，再测试组件启动失败。期望只清理本次会话，任务结果准确；获得沙箱许可后的运行失败不会转在宿主重放。
5. 仅在可丢弃环境强制结束应用，观察遗留会话。重开应保持占用而不自动接管；用户手动关闭后重开恢复。停止失败时应提示恢复方法，保留归属记录，不继续新建会话。
6. 若需要联网计算，分别核对任务开始时网络设置的冻结值。默认网络关闭，输入/请求/运行时只读，仅本次结果目录可写；用合成标记文件检查映射，勿用真实凭据做探针。

## 参考机性能与长时间恢复

固定一台x64、SSD、8GB内存及60Hz显示器作为参考机，记录实际CPU/GPU；另有120Hz设备时独立测量。使用同一份12页高分辨率合成或授权材料及代表性题库，运行安装后的Release候选产物。

- 冷启动/热启动各重复至少20次，记录从启动至可操作的原始耗时和P95；初始预算为P95不超过1.5秒。
- 连续翻页、缩放、列表滚动和切换资料，记录操作反馈（预算50ms）、缓存页返回P95（预算100ms）以及帧时间P95/P99、掉帧。60Hz按16.7ms帧预算；120Hz按8.3ms另报。保留Windows性能记录或等价原始轨迹，不能从平均FPS推出全部操作达标。
- 记录稳定空闲私有字节（目标150MiB，首轮门槛200MiB）、运行任务时应用与所属辅助进程同一时刻总私有字节（约1GiB目标）；Sandbox虚拟机/系统开销另列。工作集、GPU内存另记，注明采样间隔和可能漏掉瞬时峰值。
- 重复浏览、编辑、取消和导出至少30分钟，记录开始/峰值/结束资源及是否趋于稳定。测试只读目录、磁盘不足、文件锁定及备份恢复失败后重试；结果应清楚，成功保存内容保留，旧库和备份可恢复。
