# M0 验收与进入 M1 的条件

M0 探针用于尽早暴露技术路径风险，不是桌面产品。阶段总状态见 [progress.md](../progress.md)。任何自动测试完成都只证明对应测试范围；实际模型、沙箱兼容矩阵、资源目标与纸张打印单独验收。

## 可重复验证

开发机需要 Rust MSVC 工具链、Windows C++ 链接工具、PowerShell 7；排版探针另需 Node.js 和 Chromium／Edge，运行时构建另需开发用 Python。最终用户不依赖这些开发工具，离线产品打包属于 M5。

```powershell
# Rust 格式、静态分析、单元与本地 HTTP 协议测试
./scripts/check-m0.ps1

# 先完成两份专项说明中的依赖准备，再包含实际探针
./scripts/check-m0.ps1 -Runtime -Typesetting
```

锁文件为根 `Cargo.lock`、`probes/typesetting/package-lock.json` 与 `runtime/runtime-lock.json`。不配置供应商密钥也可以运行本地验证，合成凭据只用于环回 HTTP 测试服务。

## 验收记录规则

- 原生协议：[说明与样本来源](m0-protocols.zh-CN.md)。合成样本通过后，用户在自己的供应商账户执行同样往返，记录模型 ID、原生思考配置、真实 usage、错误与取消；不把密钥写入报告。
- 执行环境：[说明与手工矩阵](m0-execution.zh-CN.md)。只有真实 `.wsb` 启动、握手、只读映射、产物回收、取消、正常结束和会话所有权验证都完成，才能将该系统记为通过。JSON 状态机测试不证明 OS 生命周期。
- 正式排版：[数据、字体与渲染检查](m0-typesetting.zh-CN.md)。A3／A4 的 PDF 生成与屏幕检查、目标 WebView2 公式渲染、A3 100% 纸张打印分别记录。开发用 Node Typst 绑定不代表 Rust Typst 已集成。
- 资源：[测量方法](m0-resources.zh-CN.md)。采样脚本通过自检不证明产品达标。未实现的窗口、题库和大页场景持续保留“待测”，不能填写 0。

## M1 的启动门槛

1. 三种协议各有真实“图文 → 工具 → 工具结果及图片 → 完成”证据，参数不支持、鉴权、限流与取消策略明确。
2. 至少目标 Windows 10／11 环境完成沙箱桥接与所有权验证；不支持／未启用／忙碌／失败等状态区分清楚。尚无可验证所有权时，不开放自动关闭 OS 沙箱。
3. 私有计算环境在只读运行时目录、中文路径和可写缓存下绘图成功，超时与取消的整个进程树释放有证据。
4. 自包含数学和化学 SVG 到 A3／A4 PDF 的路径成立，基线、分页和题答隔离检查完成。WebView2／Rust 集成须通过最小风险探针确认；实际纸张打印单独保留到 M4 的验收，不用屏幕检查冒充打印通过。
5. 资源基线有原始数据；尚不能测量的产品场景有后续明确入口。若技术路径不成立，先修正架构记录再进入 M1。

接手者先核对专项文档中的实际结果和待测项，补齐门槛后更新 `progress.md`。不要仅因仓库已有源文件就把 M0 标为完成。
